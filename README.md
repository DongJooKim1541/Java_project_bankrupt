# 은행 업무 시스템

Java와 Oracle Database로 구현한 콘솔 기반 은행 업무 시스템입니다. 관리자와 사용자 두 역할을 두고, 계좌 개설부터 이체·입출금·환전까지 처리합니다.

- **과목**: Java 프로그래밍 (가천대학교, 2017)
- **언어**: Java 8
- **데이터베이스**: Oracle Database 11g (JDBC)
- **라이선스**: MIT

## 개요

콘솔에서 메뉴를 골라 조작하는 은행 업무 시스템입니다. 모든 상태는 Oracle 데이터베이스에 저장하며,
JDBC로 직접 SQL을 실행합니다.

로그인 화면에서 입력한 계정이 관리자 테이블과 일치하면 **관리자 모드**로, 사용자 테이블과 일치하면
**사용자 모드**로 들어갑니다. 관리자는 사용자 정보를 조회·삭제하고, 사용자는 자신의 계좌로
금융 업무를 처리합니다.

환전은 별도의 환율 테이블(`F_Money`)을 두고 국가별 원화 환율을 기록해, 두 국가의 환율 비율로 계산합니다.

## 기능

| 구분 | 기능 | 설명 |
|---|---|---|
| 공통 | 회원가입 | 이름·아이디·비밀번호·국적을 입력해 계정을 만든다. 아이디가 중복이면 거부한다 |
| 공통 | 회원탈퇴 | 아이디와 비밀번호가 일치하면 계정을 삭제한다 |
| 공통 | 로그인 | 관리자 계정과 사용자 계정을 같은 화면에서 구분해 처리한다 |
| 관리자 | 사용자 정보 조회 | 등록된 사용자 전체를 표로 출력한다 |
| 관리자 | 사용자 삭제 | 이름으로 한 명을 지우거나, 전체를 지운다. 해당 사용자의 계좌도 함께 지운다 |
| 사용자 | 계좌 조회 | 자신의 계좌를 전부 출력한다 |
| 사용자 | 계좌 생성 | `####-###-######` 형식의 계좌번호를 무작위로 만들어 개설한다 |
| 사용자 | 계좌 삭제 | 계좌번호를 입력해 해당 계좌를 지운다 |
| 사용자 | 이체 | 출금·입금 계좌번호와 받는 예금주명을 확인하고, 잔액이 충분할 때만 송금한다 |
| 사용자 | 입금 / 출금 | 계좌번호를 확인하고 금액을 더하거나 뺀다. 출금은 잔액을 검사한다 |
| 사용자 | 환전 | 환전 대상 국가와 환전 국가의 환율 비율로 필요한 금액을 계산해 출금한다 |

## 데이터베이스 구조

테이블 4개로 구성됩니다.

| 테이블 | 기본키 | 컬럼 | 외래키 |
|---|---|---|---|
| `Admin` | `Id` | `Id`, `Passwd`, `Name` | — |
| `F_Money` | `Country` | `Country`, `Rate` | — |
| `BankUser` | `Id` | `Id`, `AdminId`, `Passwd`, `Name`, `Country` | `AdminId` → `Admin.Id`<br>`Country` → `F_Money.Country` |
| `BankAccount` | `UserId`, `CreateAccountTime`, `AccountNumber` (복합) | 위 3개 + `Money` | `UserId` → `BankUser.Id` |

외래키 의존성 때문에 생성 순서는 `F_Money` → `Admin` → `BankUser` → `BankAccount` 입니다.

`F_Money`에는 원화 기준 환율이 초기 데이터로 들어갑니다.

| 국가 | KOR | USA | JPN | EU | CHN | ENG | AUS |
|---|---|---|---|---|---|---|---|
| 환율 | 1.00 | 1087.00 | 967.30 | 1292.33 | 164.48 | 1467.45 | 823.35 |

## 실행 방법

**1. Oracle 데이터베이스 준비**

Oracle Database를 설치하고 이 프로그램이 사용할 계정을 만듭니다.

**2. JDBC 드라이버 등록**

Oracle 설치 경로의 `jdbc/lib/ojdbc6.jar`를 프로젝트 클래스패스에 추가합니다. Eclipse라면
`Project > Properties > Java Build Path > Libraries`에서 넣습니다.

**3. 접속 정보 수정**

`src/bankrupt/DBConnection.java`의 `YOUR_DB_USER`, `YOUR_DB_PASSWORD`, `YOUR_SID`를 자신의
환경에 맞게 고칩니다. URL 형식은 다음과 같습니다.

```
jdbc:oracle:thin:@<호스트>:<포트>:<SID>
```

**4. 최초 1회 — 테이블과 관리자 계정 생성**

`src/bankrupt/Main.java`의 `MakeTable()` 메서드 본문이 주석 처리되어 있습니다. 처음 실행할 때는
주석을 풀어야 테이블과 관리자 계정이 만들어집니다. 이때 `Admin` 생성자에 넘기는 이름·아이디·비밀번호를
자신이 쓸 값으로 바꾸십시오.

```java
public static void MakeTable() throws SQLException {
    RelationTable r = new RelationTable();
    r.MakeTable();
    Admin ad = new Admin("이름", "아이디", "비밀번호");
    ad.MakeAdmin();
}
```

여기서 정한 관리자 아이디를 `src/bankrupt/User.java`의 `'ADMIN_ID'` 자리에도 똑같이 적어야 합니다.
회원가입할 때 이 값이 `BankUser.AdminId`로 들어가는데, `Admin` 테이블에 없는 값이면 외래키 제약에
걸립니다.

**5. 실행**

테이블이 만들어졌으면 `MakeTable()` 본문을 다시 주석 처리한 뒤 `Main`을 실행합니다. 주석을 풀어 둔 채
다시 실행하면 이미 존재하는 테이블을 또 만들려고 해서 실패합니다.

## 알려진 한계

수업 프로젝트 당시 코드를 그대로 두고 있습니다. 실제 서비스에 쓸 코드가 아니며, 다음 문제가 남아 있습니다.

**동작**

- `Main.MakeTable()` 본문이 주석 처리되어 있어, 모르고 실행하면 테이블이 없다는 오류를 만난다.
- 로그인 시 비밀번호를 `where Passwd = '<입력>'`로만 조회한다. 아이디가 존재하고 입력한 비밀번호가
  **다른 사용자의 비밀번호와 같기만 해도** 로그인된다.
- 관리자 조회 쿼리(`select Id from admin`)에 조건이 없어 관리자가 여럿이면 마지막 행을 가져온다.
- 이체와 환전이 하나의 트랜잭션으로 묶여 있지 않다. 출금과 입금을 각각 실행하고 따로 커밋하므로,
  중간에 실패하면 한쪽만 반영된다.
- 환전 금액은 실수로 계산되는데 `Money` 컬럼이 `INT`라 소수점이 잘린다.
- 회원가입 시 삽입되는 `AdminId` 값이 소스에 고정되어 있다(`User.java`의 `'ADMIN_ID'`).
  관리자를 여럿 두거나 아이디를 바꾸면 소스를 함께 고쳐야 한다.

**보안**

- 모든 SQL을 문자열 연결로 만들어 SQL 인젝션에 그대로 노출된다.
- 비밀번호를 평문으로 저장하고, 관리자의 사용자 조회 화면에 그대로 출력한다.
- 데이터베이스 접속 정보와 관리자 계정이 소스에 하드코딩되어 있다.
